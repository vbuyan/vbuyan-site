The NVIDIA device plugin assumes Kubernetes owns the GPU: it advertises `nvidia.com/gpu: 1` and hands the
card to a pod whenever the scheduler thinks it is free. When other teams use the same card outside the
cluster, the scheduler cannot see them, so it always thinks the card is free. The fix is to keep the
GPU **outside** the scheduler and make pods wait in the queue everyone else already uses.

## The pattern

1. **Describe the GPU with CDI, not a device plugin.** The card and the queue client are CDI devices,
   generated by an unprivileged user so that device permissions stay as the queue expects.
2. **Inject them through a RuntimeClass.** A `gpu-queue` RuntimeClass passes the CDI annotations from the
   pod into the OCI spec. (Pod annotations do not reach containerd by default: I learned that from a
   [failed first pod](/postmortems/2026-11-15-gpu-pod-start-cdi-annotation/).) Pods of every other class keep plain runc.
3. **Wrap the job in the queue client.** The container command starts with a small wrapper that joins
   the host queue as its own participant, waits for its turn and for free VRAM, then execs the real job
   and holds the queue connection until the process exits. When the pod dies, the card passes on.
4. **Enforce it at admission.** A CEL ValidatingAdmissionPolicy (no webhook to run or keep alive) allows
   the runtime class and the CDI annotation only in one namespace, only with exactly one container whose
   command starts with the wrapper, and only as the cluster's queue user. Pod Security `restricted` on
   that namespace removes root, capabilities and host paths.
5. **Test the bypasses, not just the happy path.** CI runs a kind cluster with the policy and tries ten
   ways around it: wrong namespace, extra container, missing wrapper, root user, and more. All must be denied.

## What it costs

Kubernetes can no longer count or queue GPUs itself, and a waiting pod holds its CPU and memory requests
while it waits. On one shared card the existing queue is the better arbiter; on a fleet, the same idea
maps to Kueue or Run:ai with an admission policy that forbids requesting GPUs outside them.
